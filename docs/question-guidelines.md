# 퀴즈 문제 교차 검증 가이드라인

`server/data/questions.json`에 문제를 추가하거나 고칠 때 모든 문제를 이 기준으로 확인합니다.
형식 규칙(글자 수, 보기 개수, 난이도 비율 등)은 [PRD 1.2절](PRD.md)을 따르고, 확인 결과는 [문제 검수표](questions-review.md)에 남깁니다.

## 모든 문제 작성 시 확인 사항

### 1. 정답이 하나뿐인가?
- 다른 해석이 가능하면 조건을 명시한다 (예: 면적 기준, 2024년 기준)
- 예: `sci-09` "사람의 체세포 하나에 들어 있는 염색체" → 염색체 이상이 있는 경우를 고려하면 "정상적인 체세포"가 더 분명하다

### 2. 최상급 표현에 기준이 있는가?
- '가장 큰', '최초의' 같은 표현에는 측정 기준을 명시한다
- 예: `geo-01` "면적이 가장 넓은 나라", `geo-08` "유역 면적이 세계에서 가장 넓은 강" (길이 기준이면 나일강과 아마존강 사이에 논란이 있다)
- 예: `geo-07` "세계 최고봉" → "해발고도 기준"이 더 분명하다 (산기슭부터 잰 높이로는 마우나케아가 더 높다)

### 3. 시간과 범위가 명확한가?
- 변할 수 있는 정보는 시점을 명시한다
- 지리적, 분류적 범위를 한정한다
- 예: `geo-03` "남한에서 가장 높은 산", `geo-05` "극지방을 제외하고 가장 넓은 사막", `arts-05` "오늘날 전하는 판소리 다섯 마당"

### 4. 교차 검증했는가?
- 의심스러운 정보는 2개 이상의 출처에서 확인한다
- 논란이 있는 내용은 주류 학설을 기준으로 한다
- 예: `hist-09` 직지는 증도가자 논란이 있지만, 현존하는 가장 오래된 금속활자본으로 공인된 주류 견해를 따른다

## 문제를 추가하는 순서

출제 문제(`server/data/questions.json`)는 카테고리마다 10문제(쉬움 4 · 보통 4 · 어려움 2)로 고정이므로, 새 문제는 후보 파일에 먼저 넣고 기존 문제와 바꾼다.

1. `server/data/question-candidates.json`에 문제를 작성하고 위 4가지를 확인한다 (Claude Code에서는 `/quiz-add <카테고리> <난이도>`)
2. `npm test`로 형식 검증을 통과시킨다
3. `npm run review-doc`으로 검수표를 다시 만들고, 사람이 출처를 확인한 뒤 검수 칸에 ✅ 또는 메모를 남긴다
4. 출제하려면 `npm run swap-question -- <출제 문제 id> <후보 id>`로 카테고리와 난이도가 같은 출제 문제와 바꾸고 서버를 재시작한다 (Claude Code에서는 `/quiz-swap`). 빠진 문제는 후보 파일로 옮겨져 다시 쓸 수 있다
