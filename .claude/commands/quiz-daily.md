퀴즈 문제 데이터의 하루 작업을 아래 1~7단계 순서대로 실행해 줘.

추가할 문제 수: $ARGUMENTS (비어 있으면 3. 1~12의 정수가 아니면 시작하지 말고 사용법 `/quiz-daily 3`을 보여 준다)

## 진행 규칙

- 단계마다 **검증** 항목을 확인한 뒤 다음 단계로 넘어간다. 단계를 시작하고 끝낼 때 "N단계 시작 / N단계 통과"를 한 줄씩 알린다
- 검증에 하나라도 실패하면 **즉시 중단**한다. 다음 단계로 넘어가지 말고, 7단계 형식으로 "실패한 단계, 실패한 검증 항목, 오류 메시지 원문, 그때까지 바꾼 파일, 되돌렸는지 여부"를 보고한다
- 출제 문제 `server/data/questions.json`은 카테고리마다 10문제(쉬움 4 · 보통 4 · 어려움 2)로 고정이다. 이 작업은 **후보 문제** `server/data/question-candidates.json`에만 문제를 추가하고, `questions.json`은 수정하지 않는다
- 커밋하지 않는다

## 1단계: 파일 구조 읽고 이해하기

- `server/data/questions.json`, `server/data/question-candidates.json`을 읽는다
- 필드와 규칙은 `server/src/game/validateQuestions.ts`(형식 검사), `server/src/game/types.ts`(Question 타입), `docs/question-guidelines.md`(내용 기준)에서 확인한다
- 필드: `id`(카테고리 접두사 `hist`·`sci`·`geo`·`arts` + 두 자리 번호), `category`, `difficulty`(easy·medium·hard), `question`(80자 이내), `choices`(4개, 각 30자 이내, 서로 다름), `answerIndex`(0~3), `explanation`(120자 이내, 1~2문장)

**검증**
- 두 파일 모두 JSON으로 읽히고 배열이다
- 모든 문제에 위 7개 필드가 있다
- 실제 규칙 값(글자 수 제한, 카테고리별 문제 수, 난이도 비율)을 `validateQuestions.ts`의 상수에서 읽어, 위 설명과 다르면 코드의 값을 따르고 보고에 적는다

## 2단계: 현재 문제 개수와 분포 확인

- 출제 문제와 후보 문제 각각에 대해 카테고리 × 난이도 표(개수)를 만든다
- 정답 위치(answerIndex) 분포도 카테고리별로 센다

**검증**
- 출제 문제가 `validateQuestions`를 통과한다 (`npx vitest run server/src/game/validateQuestions.test.ts`)
- 후보 문제가 `validateCandidates`를 통과한다 (`npx vitest run server/test/questionBank.test.ts`)
- id가 두 파일을 통틀어 중복되지 않는다
- 하나라도 실패하면 데이터가 이미 깨진 상태이므로 문제를 추가하지 말고 중단한다

## 3단계: 카테고리별 부족한 부분 파악

- 후보 문제는 출제 문제를 바꿀 때 같은 카테고리·난이도끼리만 쓸 수 있다. 그래서 **카테고리 × 난이도 12칸**마다 후보가 몇 개인지 보고, 후보가 적은 칸을 "부족한 칸"으로 본다
- 후보 수가 적은 칸부터, 같으면 출제 문제에서 정답 위치가 한쪽으로 몰린 카테고리부터 골라 오늘 추가할 칸을 정한다 (추가할 문제 수만큼, 한 칸에 최대 1문제)
- 출제 문제 중 `/quiz-validate` 기준(최상급 표현에 측정 기준이 없음)으로 바꿀 필요가 있어 보이는 문제가 있으면 그 칸을 우선한다

**검증**
- 고른 칸의 수가 추가할 문제 수와 같다
- 고른 칸마다 이유(후보 0개, 정답 위치 편중 등)를 한 줄로 적을 수 있다

## 4단계: 새 문제 추가 전 중복 체크

- 고른 칸마다 새 문제를 작성한다. 작성 규칙과 가이드라인 확인은 `.claude/commands/quiz-add.md`의 3단계(형식)와 4단계(검증 가이드라인, 웹 검색으로 출처 2개 이상)를 그대로 따른다
- 파일에 쓰기 전에 출제 문제·후보 문제·오늘 새로 만든 문제를 모두 비교해 중복을 확인한다
  - **id 중복**: 두 파일과 오늘 만든 문제를 통틀어 같은 id가 없어야 한다. 새 id는 카테고리마다 가장 큰 번호 + 1부터 쓴다
  - **정답 중복**: 같은 카테고리에 정답(`choices[answerIndex]`)이 같은 문제가 없어야 한다
  - **주제 중복**: 같은 사실을 다른 말로 묻는 문제가 없어야 한다 (예: "훈민정음을 만든 왕"과 "한글을 창제한 왕")
  - **문장 중복**: 문제 본문이 기존 문제와 거의 같으면 안 된다
- 중복이 있으면 그 문제를 다시 작성하고 처음부터 다시 비교한다. 같은 칸에서 3번 다시 써도 중복이거나, 출처 2개로 확인되는 문제를 만들지 못하면 중단한다
- 통과하면, 쓰기 전에 지금 `question-candidates.json`을 scratchpad에 복사해 둔다 (5단계가 실패하면 이 복사본으로 되돌린다)
- `question-candidates.json` 배열 끝에 새 문제를 추가한다. 두 칸 들여쓰기, `choices`는 한 줄로 기존 형식을 지키고 다른 문제는 건드리지 않는다

**검증**
- 새 문제마다 id·정답·주제·문장 중복이 없다
- 새 문제마다 출처가 2개 이상이다
- 파일에 추가한 문제 수가 추가할 문제 수와 같다

## 5단계: 문제 추가 후 형식 검증

- `npm test`를 실행한다
- `git diff --stat server/data/questions.json`으로 출제 문제 파일이 바뀌지 않았는지 확인한다
- `npm run review-doc`으로 검수표를 다시 만든다

**검증**
- 테스트가 모두 통과한다
- `questions.json`에 변경이 없다
- 검수표 생성 출력의 후보 수가 "기존 후보 수 + 추가한 수"와 같다
- 실패하면 4단계에서 복사해 둔 파일로 `question-candidates.json`을 되돌리고 `npm run review-doc`을 다시 실행한 뒤 중단한다. 보고에 되돌렸다고 적는다

## 6단계: 전체 데이터 백업

- 백업 폴더: `backups/<YYYY-MM-DD-HHmmss>/` (프로젝트 루트, 로컬 시간. `backups/`는 gitignore 대상)
- 백업할 것
  - `server/data/questions.json`, `server/data/question-candidates.json`, `server/data/banned-words.txt`: 그대로 복사
  - DB(`DB_PATH`, 없으면 `server/data/quiz.sqlite`): 파일 복사가 아니라 `better-sqlite3`의 `db.backup('<백업 폴더>/quiz.sqlite')`로 만든다. 서버가 실행 중이고 WAL 파일이 있어도 일관된 사본이 만들어진다. DB가 없으면 건너뛰고 보고에 적는다
  - `manifest.json`: 백업 시각, 파일마다 크기와 SHA-256, 문제 수(출제·후보), DB의 `scores` 행 수

**검증**
- 복사한 JSON 파일이 원본과 SHA-256이 같다
- 백업 DB를 읽기 전용으로 열어 `PRAGMA integrity_check`가 `ok`이고, `scores` 행 수가 원본 DB와 같다
- 백업 폴더 안 파일 목록이 manifest와 일치한다

## 7단계: 실행 결과 상세 보고

다음 순서로 보고한다.

1. **결과**: 성공, 또는 실패(몇 단계, 어떤 검증)
2. **단계별 결과 표**: 단계 | 결과(✅ 통과 / ❌ 실패 / ⏭️ 실행 안 함) | 확인한 내용 한 줄
3. **분포 변화**: 후보 문제의 카테고리 × 난이도 표(추가 전 → 추가 후)
4. **추가한 문제**: id, 카테고리·난이도, 문제, 정답, 해설, 출처 2개 이상, 고른 이유(3단계), 바꿀 수 있는 출제 문제 id
5. **검증 결과**: 테스트 수와 결과, `questions.json` 변경 없음 여부
6. **백업**: 폴더 경로, 파일별 크기, DB 무결성 검사 결과
7. **실패했을 때**: 오류 메시지 원문, 그때까지 바꾼 파일, 되돌렸는지 여부, 다시 실행하기 전에 할 일
8. **다음 할 일**: 추가한 후보를 사람이 검수표(`docs/questions-review.md`)에서 확인하고, 출제하려면 `/quiz-swap <출제 id> <후보 id>`를 쓰라는 안내
