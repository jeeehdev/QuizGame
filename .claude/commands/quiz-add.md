카테고리 $1, 난이도 $2인 새 퀴즈 문제를 하나 만들어 `server/data/question-candidates.json`(후보 문제)에 추가해 줘.

후보 문제는 출제되지 않는다. 출제 문제(`server/data/questions.json`)는 카테고리마다 10문제(쉬움 4 · 보통 4 · 어려움 2)로 고정이라 직접 추가하지 않는다. 출제하려면 `/quiz-swap`으로 같은 카테고리·난이도의 출제 문제와 바꾼다.

## 1. 인자 확인

- 카테고리($1): `history`, `science`, `geography`, `arts`. 한글도 받는다: 한국사 → `history`, 과학 → `science`, 지리 → `geography`, 예술과 문화·예술 → `arts`
- 난이도($2): `easy`, `medium`, `hard`. 한글도 받는다: 쉬움 → `easy`, 보통 → `medium`, 어려움 → `hard`
- 둘 중 하나라도 비어 있거나 위 값이 아니면 문제를 만들지 말고 사용법(`/quiz-add geography medium`)을 보여 준다

## 2. 기존 문제 파악

- `questions.json`과 `question-candidates.json`을 모두 읽는다
- 같은 카테고리 문제의 주제와 정답을 확인해, 이미 있는 문제와 정답이나 주제가 겹치지 않게 한다 (예: 한라산을 묻는 문제가 있으면 한라산을 정답으로 하는 문제는 만들지 않는다)
- 같은 카테고리·난이도 문제의 문체(질문 끝맺음 "~은?", 해설 말투 "~입니다.")를 따라 쓴다

## 3. 문제 작성: 기존 문제와 같은 형식

```json
{
  "id": "geo-11",
  "category": "geography",
  "difficulty": "medium",
  "question": "…?",
  "choices": ["…", "…", "…", "…"],
  "answerIndex": 0,
  "explanation": "…입니다."
}
```

- **id**: 카테고리 접두사(`hist`, `sci`, `geo`, `arts`)에 두 파일을 통틀어 가장 큰 번호 + 1을 두 자리로 붙인다. 이미 쓴 번호는 다시 쓰지 않는다
- **question**: 80자 이내, 물음표로 끝낸다
- **choices**: 4개, 각 30자 이내, 서로 다르게. 오답은 그럴듯하지만 정답과 혼동되지 않게 하고, '모두 맞음'·'정답 없음' 같은 보기는 쓰지 않는다
- **answerIndex**: 0~3. 같은 카테고리에서 정답 위치가 한쪽으로 몰리지 않게 고른다
- **explanation**: 120자 이내, 1~2문장. 정답의 근거를 쓰고, 필요하면 헷갈리기 쉬운 오답도 짚는다
- **난이도**: 중학교 교과서 수준의 기본 상식은 쉬움, 고등학교 교과서 수준이나 연도·인물을 정확히 알아야 하면 보통, 전문 지식이나 세부 사항을 묻거나 보기끼리 헷갈리기 쉬우면 어려움. 받은 난이도에 맞는 문제를 만든다
- 인구, 최신 기록처럼 시간이 지나면 바뀌는 정보는 출제하지 않는다

## 4. 검증 가이드라인 확인 (반드시 지킨다)

`docs/question-guidelines.md`의 4가지 기준을 하나씩 확인한다. 하나라도 통과하지 못하면 문제를 고치거나 다른 문제로 바꾼다.

1. **정답이 하나뿐인가**: 다른 해석이 가능하면 조건을 명시한다 (예: 면적 기준, 2024년 기준)
2. **최상급 표현에 기준이 있는가**: '가장', '최초', '최대' 등을 쓰면 측정 기준을 명시한다
3. **시간과 범위가 명확한가**: 바뀔 수 있는 정보는 시점을, 지리적·분류적 범위를 한정한다
4. **교차 검증했는가**: 정답과 해설의 사실을 웹 검색으로 **서로 다른 출처 2개 이상**에서 확인한다. 논란이 있으면 주류 학설을 따른다. 출처 2개로 확인하지 못하면 그 문제는 추가하지 않고 다른 문제를 만든다

## 5. 저장과 검사

1. `question-candidates.json` 배열 끝에 추가한다. 기존 파일과 같은 형식(두 칸 들여쓰기, `choices`는 한 줄)을 지키고, 다른 문제는 건드리지 않는다
2. `npm test`를 실행해 통과하는지 확인한다 (`server/test/questionBank.test.ts`가 후보 파일을 형식 검사한다). 실패하면 고친다
3. `npm run review-doc`으로 검수표를 다시 만든다

## 6. 결과 보고

- 추가한 문제: 문제, 보기(정답 표시), 해설, id
- 가이드라인 4가지 확인 결과를 항목마다 한 줄로 쓰고, 교차 검증에 쓴 출처(이름과 URL)를 적는다
- 이 문제와 바꿀 수 있는 출제 문제(같은 카테고리·난이도) id 목록과, 바꾸는 명령 `/quiz-swap <출제 문제 id> <새 후보 id>`
- 커밋은 하지 않는다
