퀴즈 게임 순위표를 관리해 줘.

작업: $ARGUMENTS
- 첫 단어가 작업 이름, 나머지가 인자다. 비어 있으면 `show 10`
- 알 수 없는 작업이면 아무것도 하지 말고 아래 작업 목록과 사용법을 보여 준다

## 공통

- 순위 정책은 `server/src/scoreQueries.ts`를 따른다: 게임마다 한 줄(같은 닉네임이 여러 번 나올 수 있음), 점수 높은 순 → 소요 시간 짧은 순, 점수와 시간이 같으면 같은 순위(`RANK()`), 같은 순위 안에서는 먼저 플레이한 순
- DB 경로는 환경 변수 `DB_PATH`, 없으면 `server/data/quiz.sqlite`
- 조회 작업(`show`, `find`, `check`)은 DB를 **읽기 전용**으로 연다 (`better-sqlite3`의 `{ readonly: true, fileMustExist: true }`). 일회용 스크립트는 scratchpad에 만들고, 순위는 `scoreQueries.ts`의 `RANKED_SCORES`와 같은 SQL로 계산한다
- DB를 바꾸는 작업은 `delete`뿐이고, 반드시 `npm run delete-score`로만 한다. SQL로 직접 지우거나 고치지 않는다
- 시간은 `played_at`(UTC)을 로컬 시간으로 바꿔 보여 준다. 소요 시간은 분:초
- 기록이 없으면 "아직 저장된 기록이 없습니다"라고 알린다

## 작업

### `show [N]`: 순위표 보기
- 상위 N개(기본 10, 최대 100)를 순위 | 기록 id | 닉네임 | 점수 | 소요 시간 | 플레이 시각 표로 보여 준다
- 전체 기록 수도 함께 적는다

### `find <닉네임>`: 닉네임으로 찾기
- 닉네임에 검색어가 들어간 기록을 모두 찾아(대소문자 무시) 순위와 함께 보여 준다
- 그 닉네임의 최고 순위, 플레이 횟수, 평균 점수도 적는다

### `check`: 순위표 점검
문제가 있어 보이는 기록을 찾는다. 찾기만 하고 지우지 않는다.
- **부적절한 닉네임**: 지금의 `server/data/banned-words.txt`로 `server/src/nicknameFilter.ts`의 `checkNickname`을 다시 적용해 걸리는 닉네임 (금칙어를 나중에 추가했다면 예전 기록이 걸릴 수 있다)
- **비정상적으로 빠른 기록**: 40문제를 푸는 데 걸린 시간이 문제당 평균 2초 미만(80초 미만)인 기록
- **같은 닉네임 도배**: 한 닉네임이 상위 10위 안에 3번 이상 나오는 경우
- **데이터 이상**: `correct_by_category`의 합 × 10이 `score`와 다르거나, 카테고리별 값이 0~10 밖인 기록

결과는 항목별 표(기록 id | 닉네임 | 점수 | 소요 시간 | 이유)로 보여 주고, 지울 만한 기록이 있으면 `delete` 명령을 안내한다.

### `delete <기록 id>`: 기록 삭제
1. id가 양의 정수가 아니면 멈추고 사용법을 보여 준다
2. 먼저 그 기록(순위, 닉네임, 점수, 소요 시간, 플레이 시각)을 읽기 전용으로 조회해 보여 준다. 없으면 멈춘다
3. **삭제는 되돌릴 수 없으므로 사용자에게 확인을 받은 뒤에만** `npm run delete-score -- <id>`를 실행한다
4. 실행 결과와, 삭제 후 상위 10위 순위표를 보여 준다. 서버 재시작은 필요 없다 (서버가 같은 DB를 매번 조회한다)

## 하지 않는 것

- 순위 정책(동점 처리, 닉네임별 최고 기록만 보기, 기간별 순위표 등)을 바꾸는 일은 이 명령에서 하지 않는다. 요청받으면 `server/src/scoreQueries.ts`의 `RANKED_SCORES`를 바꾸는 코드 작업으로 따로 진행하자고 안내한다
- 파일은 수정하지 않는다
